# Refinement Lab: accepted graphical design

Design accepted by the root on 26 October 2026. This document is a plan only. No new UI, simulation, model player or scenario calculation is implemented here. Functional implementation must wait for explicit root authorization after the independent audits and use only read-only validated outputs. Earlier science, games, screenshots and packages stay unchanged.

## The plain-language question

“The cap worked on that price grid. Does the same guarantee survive more precise pricing?”

The original finite certificate remains valid in its stated model. A continuous comparison asks a different, explicitly defined question. The page must make both facts visible together, rather than relabeling an earlier valid certificate as an erroneous experiment.

## Three visual steps

1. **What was certified:** show the selected original market, original grid, fixed old target and one-round activation guarantee. Link to the frozen Activation Lab and its evidence.
2. **What changes:** preserve the price interval, economy and stated tolerance, then show a different uniform grid or the continuous interval. Explain that each discrete grid recomputes its own best-profit benchmark. The grids are not necessarily nested, and finer resolution does not imply a monotone numerical sequence of worst welfare.
3. **What the continuous analysis establishes:** show the validated continuation-floor enclosure and whether the stated theorem assumptions were certified. A failed condition or unresolved comparison stays visible. No passing badge appears without the independent audit.

Use native SVG/CSS, existing colors and accessible text. A schematic price-dot row may show the idea of precision, but must state the actual grid count and clearly label any omitted points. Continuous pricing is an interval, not an invented enormous grid.

## Controls and main graphic

- Market selector: retain all eight inherited scenario labels, including grid-size variants and economically equivalent labels. Do not present them as independent economies or statistical replications.
- Target selector: retain all five original requested target labels and their stored actual F−delta thresholds, including numerical duplicates. Do not recalculate the old targets on a new grid.
- Resolution control: the nine declared grids plus a distinct Continuum view. The largest finite grid is a diagnostic, not a proof of the limit.
- Tolerance view: distinguish the primary effective payoff allowance from nominal epsilon. Carrying a fixed numerical allowance into the continuous comparison is a model definition, not a disappearing mesh error.

The main welfare chart compares the post-cap worst continuation and the range of start-specific worst values with the **fixed original actual threshold**. Clearly label the range as variation across starting public states, not a confidence interval, sampling uncertainty or the full range of all possible plays.

The continuous floor is a validated numerical enclosure under stated assumptions. Plotting its approximate location is separate from showing its exact enclosure strings in evidence details. Do not invent a numerical mesh-error band: the prospective study does not promise evaluated width/slope constants or an explicit certified mesh rate.

Offer the new mesh's own permanent competitive-cap floor only as a separately labeled comparison/toggle. A moving benchmark answers a different question from comparison with the inherited fixed target.

## Starting states and the limit

Add a small start-spread chart or readable range display so a narrow main plot does not hide residual start dependence. Explain:

> Some finite grids can retain multiple fixed points. Under the validated assumptions, their worst reachable welfare values approach a common continuous floor. This does not mean every finite grid has one basin or every permitted policy follows the same trajectory.

If showing a discrete tail, use only saved, audited map/path data and label deliberate coordinated top-choice behavior. A continuous q-star enclosure is a **limiting price enclosure**. Do not claim an exact finite jump to its boundary, fabricate a continuous execution, or introduce an API/account-backed game player.

A low-customer-benefit continuation is not necessarily jointly profit maximizing or beneficial to each seller. Show individual profits only where the validated data supplies them and retain the unilateral-deviation limitation.

## Evidence and explanations

Keep an accessible drawer for the whole-interval assumptions, source/input hashes, independent audit, nominal/effective tolerance, root brackets and actual threshold comparisons. Clearly distinguish the exact imported binary64 constants interpreted as real values, validated continuous enclosures, and ordinary floating-point mesh diagnostics.

Use a short explanation of three different objects: a learner's training outcomes, a fixed learned pair's attractors, and this guard's all-policy continuation values. The page concerns the third. It does not show emergence, incentive-compatible collusion, real-market prediction or a new learning algorithm.

## Implementation and verification gate

Once authorized, build a separate read-only page and display exporter; root owns routes and scientific figures/report. Preserve the old UI. The exact file list and final schema should be agreed from audited outputs, rather than guessed from an unfinished run.

Verify actual module logic across every market, target, resolution and retained failure. Then perform actual desktop and narrow browser checks, keyboard selection, precise legend/bound labels and screenshots. Keep source/DOM-adapter tests separate from rendered-browser observations, child CSS viewports separate from device emulation, and developer checks separate from human understanding.
